# Decisions

One line per decision that the original spec left open.

## Project and workflow
- The folder was already a git repo with history, so it was reused instead of running `git init`.
- The old requirements.txt was a UTF-16 `pip freeze` from PowerShell with torch and earthengine-api pins; replaced with a short UTF-8 list of minimum versions, without torch.
- Added `common.py` (shared logging, status, download, raster and boundary helpers) and `summary.py` (stage `summary`) so the same code is not copied into every script.
- Smoke runs write to `outputs/smoke/` and `results/smoke/` (gitignored) so tiny test numbers can never mix with real results.
- Smoke mode uses the GPU if one exists (so the AMP code path is checked at home); on a machine without CUDA it runs on the CPU.
- `check_env` and `summary` always rerun (no marker) because they describe the current state.
- A stage that returns NOT RUN (for example a missing IDSP file) writes no marker, so it runs again automatically once its input exists.
- Network errors are retried with growing waits, except 401/403/404-type errors which cannot fix themselves.
- `results/norm_stats.json` is committed: it is small, generated by code, and documents the exact numbers used on Assam.

## Model 1
- Radar clip range -50 to +5 dB (the example in the spec); NaN/inf pixels become 0 after normalization (the training mean).
- Optimizer: AdamW, one learning rate 3e-4 for all layers, weight decay 1e-4, cosine schedule over the max epochs (simplest stable choice).
- Water IoU is pooled over all valid pixels of a split (micro IoU); the mean of per-tile IoUs is also saved in `model1_metrics.json`.
- Test comparison mask: pixels where the hand label is 0/1 AND the Otsu label is 0/1, identical for U-Net and Otsu.
- Example and data-check tiles are picked with a fixed random seed (at least one India tile), not by hand.
- District boundaries: geoBoundaries first (verified to contain all seven candidates, including Majuli, created in 2016), GADM 4.1 as fallback, then the bbox in config.py.
- Normal-year windows use the same calendar dates as the flood window (25 Jun to 10 Aug).
- Scenes are grouped into passes by local solar date; scenes of the same pass are mosaicked by odc-stac (first valid pixel wins).
- A pass counts only if its scenes cover at least 95% of every chosen district.
- District auto-choice: among connected (touching) groups of 2-3 candidates, pick the orbit+group with, in order: every normal year covered, most flood dates, more districts, most normal dates.
- Pixels outside the chosen districts (plus a 500 m buffer) are stored as NaN and their chunks are never downloaded, to save disk and time.
- The "water-ish" check uses VV < -18 dB; it is only a sanity check, never used for mapping.
- GRD fallback applies the sigmaNought calibration LUT and GCP warping only (no thermal noise removal, no terrain flattening); it is flagged in STATUS when used.
- Overlapping inference tiles are averaged; big rasters are processed in 4096 px blocks with a 64 px margin that is cropped off.
- Pixels never observed in a normal-year pass are treated as no data in all flood products (we cannot tell flood from permanent water there).
- Flood blob cleanup uses 8-connectivity; 0.5 ha = 50 pixels at 10 m.
- Duration: run from pass i to j = (date j - date i) + median revisit interval; a pixel with no radar data in a pass breaks its run.
- Spatial plausibility test: on a 50 m grid, mean distance to normal water (and mean elevation) of flooded cells vs 200 random draws of the same number of land cells; one-sided permutation p-value.
- DEM: Planetary Computer `cop-dem-glo-30` first, then the public AWS Copernicus bucket. JRC GSW: Planetary Computer first, then the public GCS tiles.
- Sentinel-2 check: MNDWI > 0 is water, SCL classes 4-7 are clear, compared on a 20 m grid; the +1000 reflectance offset is removed for processing baseline 04.00 and later.

## Model 2
- OSM query uses nodes, ways and relations (`nwr ... out center`) so villages mapped as areas are included; points with identical coordinates are deduplicated.
- Grid fallback keeps only 1 km cells that contain a populated WorldPop pixel (or all cells if WorldPop is unavailable).
- Open Buildings: the v3 "points" files (centroid, area, confidence) are used instead of polygons because counting only needs centroids (about 1 GB instead of 3.6 GB for Assam).
- Exposed people = for each WorldPop pixel centre, its population times the flooded share of the 100 m block of the flood grid around it.
- `mean_duration_days` is the mean duration over the flooded pixels of a unit (0 if none flooded).
- `first_flood_date` is the first pass in which at least 1% of the unit is flooded.
- `elev_pctile` is the percentile of the unit's mean elevation within its district.
- WorldPop file URL is asked from the WorldPop REST API at run time (aliases tried in order); hard-coded URLs are only fallbacks; a hand-downloaded file in `data/manual/` wins.
- WorldPop is read remotely for the AOI window only (GDAL /vsicurl/) and the small clip is cached; the full India file is downloaded only if windowed reads fail.
- No Census 2011 drinking-water table could be fetched reliably (censusindia.gov.in and data.gov.in were unreachable here and need manual steps), so the code reads a hand-filled `data/manual/census_water.csv` or excludes the feature.
- Percentile ranks give tied values the lowest rank, scaled (rank - 1) / (n - 1), so all zero-flood units get 0 instead of a middle value.
- If one unit lacks one value (for example no DEM), its weights are renormalized over the values it has.
- Static components (well reliance, elevation) are used from the first pass; duration only from the second pass; with a single flood pass duration is dropped entirely.
- `ranking_by_pass.csv` is stored wide (one row per unit, one rank/score column per pass) to keep the file small.
- IDSP: water-borne diseases are chosen by keywords in `config.py`; keywords of 3 letters or fewer (like ADD) must match as whole words.
- IDSP duplicates: exact duplicates first, then rows with the same district, date, disease and case count.
- Outcome window: flood start to flood end + 4 weeks, truncated to the file's own coverage (with a warning).
- Baselines B1 and B3 are aggregated to districts the same way as the index (mean of the top-decile units, and overall mean); B2 rainfall is the mean of report rows in the window (only districts with rows).
- Permutation p-values are exact (all orderings) when n <= 8 districts, Monte Carlo otherwise.
- District-week design: exposure is the index (top-decile mean) after the latest pass on or before the end of the week; outcome is any outbreak in the next 3 weeks; weeks before the first pass are left out.

## This machine (school laptop / cloud check)
- Verification here used Python 3.12 in `.venv`.
- Planetary Computer, GADM, OSM Overpass, WorldPop, ImageNet weights and the Indian government sites were blocked by this environment's network policy; Google Cloud Storage, AWS Copernicus DEM and geoBoundaries (via media.githubusercontent.com) worked.
- Because the full Sen1Floods11 data could be downloaded here, the full `get_sen1floods11`, `train` and `test` stages were also run on the CPU here with a randomly initialised encoder (ImageNet weights blocked). Those results are real but are a CPU baseline; the GPU run at home overwrites them.
- Smoke box: a 5 km box with its centre in Majuli, picked from JRC GSW so that about a third is permanent water (so the smoke quick-look shows a river).
